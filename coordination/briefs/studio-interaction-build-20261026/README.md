## KAIRO actions and context

Teach me: choose an available scope and a venue (Here or Classroom); show a bounded outline and source context before generating. Explain this: selected part/passage defaults; ask for a smaller step without losing citations. Test me: scoped questions, attempt before answer, hints identifiable, save is explicit; no mastery claim. Plan my next step: use actual work/preferences/role goal, explain why, no employment promise. More actions may expand as a normal list after these work; do not overload a second arc.

Scopes are selected part/passage, current section, reviewed lesson, or a topic grounded in chosen reviewed material. A topic without material must be identified as general help, not source-backed. Whole document does not silently mean whole-document visual understanding; the planner exposes actual coverage and limits. Source selection never crosses the authenticated owner. Lesson/practice edits preserve revisions and source integrity.

## Tablet and motion acceptance

Teach: retrieve tablet, glance/tap, then reveal board when its content is ready. Explain: orient toward the real target, briefly highlight it and reveal one diagram. Test: tablet cue prepares a question; neutral awaiting-answer pose does not hint at the correct option. Loading: keep current content and a truthful stage label (checking sources/preparing lesson only while actually running); cancel available. Success: a small acknowledgement after durable save, not before. Error: stop decorative animation and show plain recovery; no false completion flourish. Compact/reduced-motion: one readable pose and immediate state change; all functions remain.

Tablet retrieval/hand contact is a new authored skeletal animation task. Do not claim a completed interaction from a static prop or generated image. A speaking face, sign translation, gestures and simulation validity each require their own evidence.

## Working loop, with bounded checks

At each boundary: inbox/current main/status -> choose one ready nonoverlapping package -> register actual settings -> claim exact scope -> read interface/refs -> implement -> meaningful actual-module tests -> one batched desktop/mobile check -> repair observed issues -> one confirmation pass -> publish exact SHA/draft PR/handoff -> independent root review -> integrate -> targeted/full release checks -> deploy authorized exact image -> report actual behavior and next package. No endless polishing, synthetic users as traction, silent scope expansion or claims that a chat received a bus message. If blocked, record exact blocker and continue independent work; never take another owner's claim.

Every handoff states criterion, learner need, acceptance, actual evidence, unknowns and next dependency. Completed UI packages remain unmounted until root says otherwise. Existing chats receive explicit scoped messages; idle/declined chats are not reported as working. No guessed model settings.
