# Coursework sources and tool foundation

Owner codex-sources-20261021; model/effort unknown because exact settings were not exposed. Task SOURCE-001. No shared app UI, npm manifests or Engineering-owned files changed.

## Authorization and data placement

The user authorized reading personal coursework in Desktop/Downloads, UNISA second-year, assignments, course-coded files/folders and coursework screenshots. Discovery selected those course locations and matching Downloads/loose Desktop files, with metadata-only inspection of other immediate directory names. Obvious academic/registration/identity material was excluded from ingestion. Originals were not renamed, edited or deleted. No private document was uploaded to a cloud/model provider.

Private inventory, text, OCR, rendered pages and quality reports are under data/private/course-sources/, ignored by Git and outside public web assets. Do not paste that corpus into another model/service or move it into studio/public on the strength of this local test. This task did not create a cloud dataset or train a model.

## Actual results

- Filename/context discovery: **537 candidate course files**, not a deduplicated content count; **21** detected course codes. Formats: 415 PDF, 70 DOCX, 36 PNG, 6 Markdown, 5 text, 4 XLSX, 1 PPTX. **2,091** screenshot images have private metadata records and mostly remain unclassified. Four personal-record filename candidates were excluded.
- Primary extraction pilot: **24 documents**, **41 pages/sections**, **105,452 characters**, **102 cited chunks**. Methods exercised: native PDF text, Word, text/Markdown and bounded read-only spreadsheet cells. All content remains reviewable/unvalidated.
- One apparent PDF failed because its content was DOCX. Content sniffing was added; targeted recovery parsed it as Word without changing the original. The primary pilot then had zero remaining errors. Initial/recovered results are distinguishable in the private report.
- Screenshots: **24 sampled**, **4 OCR coursework candidates**. Two were visually confirmed as genuine coursework examples: an economics diagram/MCQ and an auditing ethics scenario table. Expected visible text markers were present in OCR. This is not full graph/table interpretation or answer validation. The other candidates were not promoted to reviewed coursework merely for containing a course code.
- Separate scanned-paper probe: **2 pages**, both rendered and processed through RapidOCR; **3,507 characters**, **4 chunks**. The first rendered page was visually inspected, including printed SQL options. Exact symbols/MCQ wording and question dialect still require review; no answers were generated or graded.
- Separate PowerPoint probe: **2 slides**, **166 extracted characters**. Slide text reading was exercised; diagrams/images are not interpreted by this XML-text path.
- RapidOCR 1.4.4 is installed in a project-only system-site-packages venv, with its OCR wheel/bundled models and dependencies. The native Windows OCR script was blocked by local script authorization; policy was not weakened. Initial uv setup failed on its default cache, so standard venv and an explicit project cache were used. No GPU or cloud OCR service was needed.

## MCP and validation

Built a read-only stdio server with source_catalog, search_coursework and read_source_chunk, using existing MCP Python SDK 1.23.3. Source/chunk IDs are validated; tools do not accept arbitrary filesystem paths or expose write/shell/upload operations. Catalogue output omits original private paths. Retrieved content is labelled untrusted source data with review flags.

Five retrieval/boundary tests passed: exact source spans/page citations, omitted private path in catalogue, rejected arbitrary-path/unknown-ID input, no invented unmatched evidence and chunk offset/overlap preservation. Repeated after extraction fixes: 5/5 passed.

The first local SDK subprocess check stalled under the Windows sandbox before a server process started. Only the identified test process was stopped after its command line was verified. The same bounded stdio check outside that sandbox passed protocol initialization, exact tool discovery, catalogue/search calls and arbitrary-path rejection. No port or external host configuration was opened. The client's output printed counts/status only, not private excerpts. claude-mcp.example.json remains an example; KAIRO and Claude are not automatically configured to use it.
