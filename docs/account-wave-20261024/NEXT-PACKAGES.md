# Additional bounded packages once capacity is free

This is a prioritized queue, not a statement that these tasks are already running. Root rechecks claims, publishes any shared interface and assigns no more than two parallel implementation workers. Existing chat and worker lanes remain nonoverlapping. Every package preserves KAIRO/C identity, source integrity, reading/caption alternatives and the browser-observation restriction.

| Priority/package | Learner need and likely feeling | Bounded supporting work | Observable acceptance and dependency | Criteria |
|---|---|---|---|---|
| 1. Account lifecycle failure matrix | “Did signing out really stop my account being used?” | Deterministic tests for session refresh, disabled/revoked account, pending sign-in, reset recovery and account switch; root owns SDK/backend implementation | No late result or old account record enters new session; expired/revoked identities rejected according to documented policy. Needs root account-host interface first | Product, Usability, Sustainability |
| 2. Per-account source isolation | “Is my material private?” | Two-account read/write/delete/export/revision tests against root repository adapter; no provider/router ownership | Same IDs under different identities cannot cross-read; switching account clears account cache; local records never silently migrate. Needs owner-scoped material contract | Product, Usability |
| 3. Import and cancellation edge cases | “Why did my upload stop, and what can I recover?” | Synthetic mixed native/scanned PDF, rotated image, formulas, PPTX notes/chart, DOCX table and sparse XLSX fixtures; job-state transition tests | Coverage distinguishes failed/skipped/OCR/visual work, retry deduplicates jobs, cancel ignores late result, bounded memory/time. No private learner documents or arbitrary uploads to external models | Product, Intelligence |
| 4. Citation and editing evaluation | “Which words actually support this answer?” | Fixture pack for changed source revision, exact quotes, copied diagrams, edited formula, unsupported claims and retrieval misses | Every citation resolves against immutable reviewed revision; no answer marked supported only because a citation ID exists. Needs current output schema; subject expert adjudicates correctness | Product, Intelligence, Impact |
| 5. Engineering teacher bridge | “KAIRO should help with the part I selected.” | Source/scene-state teaching contract tests plus authored snippets for current motor/pump controls | A named selection/variable produces a source-backed explanation and permitted highlight/action; unsupported actions fall back clearly. Root owns provider/scene orchestration; no competing studio editing | Creativity, Intelligence, Presentation |
| 6. Reading/mobile/low-bandwidth fallback | “I can keep learning when 3D or speech fails.” | Source-only accessibility and state tests, reading parity, reduced-motion and deferred asset-loading proposals | Reading remains complete and keyboard-operable; missing WebGL/audio/network never loses answer/position. Browser/device validation remains a separately authorized gate | Usability, Impact |
| 7. Push-to-talk adapter tests | “When is it listening, and what is sent?” | Mic lifecycle/abort/VAD/transcript-confirmation tests using injected doubles; no real recordings | Permission and cloud-send consent distinct; stop ends tracks and pending work; transcript editable; locale failures have text fallback. Requires published root ASR adapter; no unsupported SASL claim | Usability, Impact, Intelligence |
| 8. Per-user cost and quota tests | “Will an action suddenly cost money or stop halfway?” | Durable reservation/idempotency/rate-limit fixtures and a measured synthetic request-cost worksheet | Duplicate retry not double-charged; hard app quotas and explicit provider choice; no silent paid fallback. Root owns provider secrets/cloud configuration | Sustainability, Product |
| 9. Curriculum onboarding | “Show my course and year, with a useful way to correct it.” | Pure registry lookup/filter component and tests for shared modules, institution/year and unknown course | Exact course codes and original syllabus links preserved; no invented enrolment or credit equivalence. Needs account-profile contract; current registry is not a full degree database | Usability, Intelligence |
| 10. Rights-cleared learning packs | “Give me something useful before I upload.” | Small public-source acquisition/attribution manifests and authored practice after item-level rights checks | Hash/licence/edition/source anchors retained; local/offline pack works; external terms and asset exceptions respected. No bulk training from public access alone | Product, Creativity, Presentation |
| 11. Optional learner analytics | “My progress should help me without exposing my material.” | Minimal event schema, redaction/deletion tests and BigQuery query templates with dry-run/max-bytes caps | No names/emails/files/raw answers/audio; purpose and retention explicit; descriptive baseline before predictive ML. No collection or BigQuery provisioning just from this queue | Intelligence, Sustainability, Impact |
| 12. Opportunity freshness | “Is this bursary or job still open and relevant?” | Official-source metadata fixture, checkedAt/closing date/expiry/relevance presentation | Original link, date checked and uncertainty visible; no invented award or employer partnership, no automatic application or unrestricted social scraping | Product, Impact |

The critical path remains account host → owner-scoped material/lesson history → complete hosted source-to-engineering journey. Backlog work must support this path rather than grow disconnected features. Public launch, real-user validation and subject-matter acceptance remain separate from automated checks.
