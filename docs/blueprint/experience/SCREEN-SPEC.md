# Screen catalogue — experience/1

**112 states · 8 areas · 7 guided journeys.** Generated from the same screen contract as the clickable prototype. A state can become a route, drawer or modal; do not interpret this inventory as a requirement for 112 separate frontend pages.

## Shared interaction rules

All main actions are verb-first and name the result. A secondary action preserves context. Reviewer Previous/Next links traverse the catalogue or chosen journey and are outside production navigation. A source, answer, practice attempt or evidence item keeps its source/version/assistance context. Do not enable a service action simply because its design state exists.

Forms require inline errors in the live app; only sample input is supported here. Success/error, loading, empty and permission states must reflect confirmed system state. Auth, microphone, sharing, provider connections and applications are simulated in the design preview. The design does not imply a screen-reader, browser, phone or voice acceptance pass.

## Patterns to preserve across variants

- **Teacher:** gaze and gestures communicate an actual lesson/listening state; captions and reading controls stay usable without 3D. The same question can be typed. Source drawer never obscures the only way to pause.
- **Source review:** desktop side-by-side, phone original/text tabs; preserve page, confidence/uncertain spans, edit history and selected revision.
- **Lesson and passage:** focusable anchors offer the same actions as pointer selection; no hover-only requirements. Explain, translate, note and source controls do not silently change the source.
- **Practice:** show the task before feedback, preserve attempts and help used, explain the rubric. The preview quiz computes its answer feedback locally; the case-feedback page is an authored worked example, not a dynamic evaluator.
- **Evidence:** label supported practice, independence, author confirmation and external review separately. Do not make a verified-looking badge from activity alone.
- **Role and CV:** sample direction demonstrates evidence gaps without a fabricated match percentage, current vacancy or ATS guarantee. Live scoring requires reviewed sources and a rubric.
- **Settings:** preference changes need an explicit save/confirmation state in the live app; use capability-aware language options. Keep preview-only choices from masquerading as live features.
- **Recovery:** preserve drafts and last successful save, identify the failed action and offer a usable next path. Do not claim that a save succeeded until storage confirms it.
- **Provider/action consent:** explain exact purpose/data/destination and let the learner revoke it. No hidden recording, file upload or external form submission.
- **Responsive:** one column on phone, touch targets at least 44 px, no cut-off primary action; long text wraps; visible focus and 200% zoom review required.
