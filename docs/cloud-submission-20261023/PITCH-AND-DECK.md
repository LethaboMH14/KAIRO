# KAIRO pitch, advert and deck production plan

## The 20-second hustle video

The user's advert idea fits the selling purpose, but the programme p3 says record yourself. Safest submission: real user on camera, with app footage, layered notifications and a polished edit. An entirely generated presenter is not assumed eligible. Use one voice and readable captions; original/licensed music only. A team-profile song preference is not a synchronization licence. No generative asset or paid model call is authorised by a downloaded asset's instructions.

Forty images in five seconds would be roughly eight images/second: most messages would be unreadable. Use 3–5 deliberate problem signals, then one coherent demonstrated solution. Keep the initial story about understanding and practice. Funding/job rejection can appear in a longer labelled vision piece, but cannot suggest live deadline alerts or guaranteed jobs/marks in today's prototype.

## Longer advert / presentation opener (60–90s target)

0–10s: real learner, information overload, limited chance to practise, uncertainty about next step. 10–20s: one sentence problem and engineering-first target. 20–45s: actual reviewed-source → lesson → motor → calculation → practice flow. 45–60s: evidence/resume and reading/drawing alternatives. 60–75s: proposed curriculum-to-career direction visually separated as 'Next'. 75–90s: honest pilot proposition and invitation to try the verified demo. Proposed funding/opportunity/portfolio features remain labelled; no fake testimonial, acceptance email or grades-before/after claim.

Prefer deterministic motion compositions of real UI and original graphic panels. Generate at most a few generic illustrative inserts after approved model/price/rights review; they are supporting media, not evidence that an app capability exists. Don't spend all $13 on untested video models. Root's cloud architecture has a proposed $4 media allowance, not a promise that a specific model duration fits. Review output before reuse; only rights-cleared footage/audio goes in the submission.

## Deck: content ready for the user's upcoming Figma reference

Use current selected C/Manrope/Chalk-Moss-Sage as baseline. User will supply the preferred REEFPRINT/KHANYA-style presentation reference; do not invent that reference or silently copy unrelated templates. This is the content/production plan, not a final Figma/PPTX/PDF artifact.

1. **KAIRO — make knowledge workable.** One motor/learner image, one sentence; no inflated claim.
2. **The learner's gap.** Access to information versus supported understanding/practice; actual source evidence and pilot question, not invented statistics.
3. **Meet one learner.** Adult engineering learner, reviewed module/material and explicit goal; illustrative persona labelled.
4. **One journey.** Source → review → lesson → inspect → practise → evidence → resume; show what is implemented and what remains hosted work.
5. **The interaction that matters.** Selected part, change a supported parameter, predict/check/explain; source and simulation limits.
6. **Intelligence with evidence.** Structured generation, source checks, transparent adaptation and separate experimental ML; actual evaluation, no fake accuracy.
7. **Architecture and privacy.** Rendered topology, identity/owner boundaries, model placement and durable jobs; distinguish target from active infrastructure.
8. **Business and unit economics.** Named buyers, price-test hypotheses, measured cost plan and sensitivity; zero unverified traction.
9. **Validation and next steps.** Actual automated results + open user/device/SME/pilot checks. Every criterion has a concrete proof or explicit gap.
10. **Try it / ask.** Real final URL, dedicated demo-account details and tested QR; ask for a bounded engineering pilot/mentor feedback. Credentials only in intended private submission, never public repository.

Embed video only where the selected presentation format supports it. PDF needs a usable link/QR and static fallback because embedded animations/video may not play. PowerPoint needs local media/codecs verified after export. A 20-second video, cinematic advert and functional demo serve different purposes; none replaces a required usable app or portal form. Final media formats, duration, caption/audio levels, links, QR and permissions require actual export checks. No final footage, presenter recording, rendered MP4 or public demo is claimed by this plan.
