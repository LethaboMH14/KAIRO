# Goal-relevant source evidence selector

`selectEvidence(source, goal, options?)` is a synchronous, deterministic lexical selector. It tokenizes the learner's goal, scores reviewed text chunks by distinct shared terms, and resolves ties in original source order. Lexically ranked results stay relevance-ranked so downstream lesson consumers that take the first few citations retain the useful passage; locators and exact source offsets still identify each excerpt's position in the source. If the goal has no usable matching term, results are in source order. This is transparent lexical matching, not semantic retrieval, an ML model, or a correctness judgment.

The selector requires `reviewed: true`, a 64-character hexadecimal revision, well-formed pages (each at most 16,000 code units and each locator at most 300), no more than 100 pages, and at most 48,000 UTF-16 code units in total. Goals may be empty (source-order fallback) but cannot exceed 1,000 code units; at most 64 distinct meaningful goal terms are used. Matching uses locale-independent `toLowerCase()`. It returns exact source substrings and JavaScript UTF-16 `start`/`end` offsets. IDs retain `S<sectionIndex+1>-<start>`. Each candidate chunk is at most 1,400 code units. Defaults are 12,000 selected characters and 12 chunks; caller limits are clamped to 1–12,000 and 1–24. The last selected chunk is clipped to any remaining character budget without splitting a Unicode surrogate pair. The returned scope and omitted-character count make the bound visible.

The SHA-256 revision is a shape check here. The root integration owner must verify that the reviewed page collection is immutable and that `revision` matches `SHA-256(JSON.stringify(reviewedPages))` in the existing version store **before invoking this selector**. This synchronous helper does not calculate or authenticate the hash, use `node:crypto`, or establish source integrity by itself. A matching revision string supplied by a caller is not proof unless the root gate verified it.

The selector treats source text only as data. It has no model, provider, network, browser, or tool-execution path and does not follow instructions found inside source material. Returned excerpts are supporting spans for the selected goal, not authoritative answers.

Judging mapping: **Intelligence** (transparent goal-conditioned evidence retrieval) and **Product/Usability** (help a learner find the relevant reviewed passage). Acceptance evidence is the focused deterministic suite in `studio/tests/evidence-selection-core.test.mjs`, including relevant content beyond 12,000 characters, exact offsets, Unicode, editing state, ties, fallback, invalid inputs and budgets. Human review of usefulness, source integrity at the integration boundary, and end-to-end lesson acceptance remain open.
