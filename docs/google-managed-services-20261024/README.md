# KAIRO managed-services decision memo

**Research date:** 24 October 2026  
**Scope:** official Google documentation and list-price comparison for KAIRO's one-learner to small-pilot hosted path. This is a recommendation, not an implementation or a billing estimate from the project account.

## Decision

Use the hosted foundation already selected by the parent: Firebase Authentication with Identity Platform for sign-in, Cloud Run in `africa-south1` for the web API, Firestore Standard in `africa-south1` for owner-scoped metadata and version/job state, and the existing private Johannesburg Cloud Storage bucket for source originals and derived artifacts. Keep the local SQLite workspace local-only. Do not add Cloud SQL, Document AI, Agent Search or Vertex RAG Engine to the first hosted pilot. Keep inference and speech behind explicit consent, a source/revision boundary, request limits and an honest reading fallback.

The parent reports that the default Firestore Standard database in `africa-south1` was created with `freeTier=true` and Identity Platform email/password sign-in was initialized. This is newer parent-provided state than the 23 October cloud-foundation document, which said the Firestore inventory was empty. This research did not inspect the live project, so the new state is **reported, not independently verified here**. Do not create another database or repeat the Auth setup. Preserve a root-owned verification receipt as the authority for exact resource state.

This combination is the shortest path for the current JSON/history-oriented workspace and a small pilot: it avoids converting the existing SQLite semantics immediately, uses server-derived Firebase identity, and keeps heavy files out of document records. It still needs root-owned integration and two-account security/restart tests. Firebase Auth is not authorization; App Check is not user identity; a Firestore document path is not a security boundary on its own.

- No billing console, credits, project APIs, secrets, learner data, or private files were read. No cloud resource or project setting was changed. “After credits” below means the sustainable list-price/free-quota position with **zero promotional credits assumed**; it is not an account invoice or a claim that the free quotas are unused.
- Public official Google documentation was searched/read as text for this memo. No browser UI, browser automation, service/API call, model call, private document upload or benchmark was run.

## Recommended one-learner to small-pilot shape

1. **Sign-in:** keep the parent-initialized email/password method for the first internal path. The web client obtains a Firebase ID token; the backend verifies the token cryptographically, checks audience/issuer/expiry, and derives `uid` itself. Worker A's middleware only adds claim checks around an injected verifier; root still supplies and tests actual cryptographic verification.
2. **Abuse layer:** start App Check in monitoring mode after the real web client and backend token verification are wired. Inspect valid/invalid traffic before enforcement. Use App Check alongside Auth, never instead of it. Require its token on the custom API only after local development/approved origins and recovery behavior are accounted for.
3. **Metadata:** use the already-provisioned Firestore default Standard DB for owner-scoped source metadata/revisions, lesson drafts/versions, jobs, and small progress records. Keep each document bounded. Admin SDK bypasses Firestore Security Rules, so server repository methods must verify ownership on every read/write/delete/export and retrieval query. Prefer transactions/CAS for immutable source revisions and draft versions.
4. **Files:** keep originals and large extraction/lesson artifacts in the existing private regional GCS bucket using server-generated opaque object IDs and owner checks before signed URL issuance. Keep the seven-day soft-delete window visible in the eventual retention/deletion copy and budget for soft-deleted bytes.
5. **API:** when the owner-scoped service is ready, run the container on Cloud Run with request-based billing, `min-instances=0`, a conservative `max-instances`, explicit per-user upload/token/page quotas and request deadlines. The local writable filesystem is memory-backed and ephemeral, so it cannot host durable SQLite or uploads.
6. **Long work:** first use synchronous extraction only where it reliably fits a request deadline. Move longer work to a private Cloud Run worker called through Cloud Tasks, with OIDC service identity, an idempotency key, immutable source revision, cancellation/stale-revision checks and persisted job state. Put only opaque IDs/revision/hash/limits in the task body, never the file bytes. Use Cloud Run Jobs later for backfills or batch work, not ordinary single-source ingestion.
7. **Model/speech:** keep the current consent-gated generation flow as a separately bounded feature. Before sending any hosted private material, identify the exact model, endpoint/location and retention configuration. Do not route silently to a different vendor or global endpoint. Reading remains usable when model, speech, network or quota fails.

## Cost worksheet: how to budget after credits

There is no reliable single monthly total until traffic, file volume, API use, model, region, retention and account-level free-tier consumption are known. Use USD list prices, treat promotional credits as **zero**, and calculate the following independently. The table below makes the ongoing no-credit position explicit; free-tier rows are service allowances, not credits or guaranteed remaining quota.

| Component | Sustainable monthly formula | Small-pilot interpretation |
|---|---|---|
| Identity Platform | `max(0, monthly active users − current eligible no-cost MAU allowance) × the exact provider price`; add phone SMS only if selected | One email/password learner should be below the currently listed MAU allowance, assuming the project is on the relevant plan and no conflicting billing setup. |
| Firestore Standard | `billable reads × regional read rate + writes × regional write rate + deletes × regional delete rate + avg indexed GiB × storage rate + egress + optional TTL/PITR/backup/restore` | One learner may remain inside free-tier operation/storage quotas, but transactions/query patterns, indexes and account-wide quota usage determine invoice. |
| GCS | `GiB-hours × Johannesburg class rate + Class A/B operation count × rate + egress/retrieval + soft-deleted GiB-hours` | A few small originals may be low cost, but retained soft-deleted objects and downloads still count. Price the chosen class and real retention before admitting private files. |
| Cloud Run API | `billed vCPU-s × regional rate + billed GiB-s × regional rate + request count + network/build/artifact/logs − eligible free usage` | Min-zero request billing avoids idle instances, not all costs. Include build/deploy and test calls. Set hard per-user request and upload limits in code. |
| Cloud Tasks/worker | `billable task API/delivery chunks × $0.40/M above first 1M + Cloud Run worker CPU/RAM/time + GCS/Firestore operations` | Queue APIs and delivery attempts count separately; retries count. Make duplicate dispatch harmless. |
| Gemini generation | `input tokens/M × chosen endpoint input $/M + output tokens/M × output $/M + image/audio/video tokenization + any extra grounding/storage` | Example above: 100 lessons × (5k input + 1k output) = 0.5M input/0.1M output; Gemini 3.8 Flash global introductory list ≈ $0.75 through 2026-12-31, then ≈ $1.50 from 2027-01-01. Non-global ≈ $0.825 then $1.65. This is token-only and does not promise that model/region is available. |
| Document AI | `pages × processor-specific rate + storage/worker/egress` | OCR has its own threshold; layout is a separate charge. Do not run it over all pages by default. |
| STT/TTS | `max(0, transcription minutes − eligible free minutes) × V2 selected no-logging rate + max(0, synthesized chars − voice-specific free chars) × voice rate` | Example: 100 STT V2 standard min with remaining 60 free mins = $0.96 for no-data-logging. Regional/location/edition/processor and effective dates matter; re-check before purchase/deployment. Google free usage tiers are generally pooled at project/account level and may be consumed by other workloads. A budget alert is not the pilot's spend ceiling.

## Now / later / reject

### Now

- Keep the parent-reported Firestore Standard `africa-south1` default database and Identity Platform email/password configuration; root should reconcile them with its own cloud evidence before relying on them. No duplicate creation.
- Keep owner-scoped source/draft/job data in Firestore and file bytes in the existing private Johannesburg bucket; implement only through the root repository and Worker A's verified token boundary.
- Finish a request-based, min-zero Cloud Run API in Johannesburg with strict max instances, timeouts, upload/page/token quotas, redacted logs and no durable local files.
- Apply per-user quotas and budget alerts; do not treat billing alerts as enforcement. Keep reading, source review and local-mode fallback.
- Add Secret Manager for actual runtime secrets when needed, least privilege per secret, no key files.

### Later, gated by evidence

- Cloud Tasks plus a private worker when bounded local extraction does not fit an HTTP request; require idempotency, cancellation, stale-revision rejection and retry evidence.
- App Check enforcement after monitoring establishes valid-client behavior and a safe local/developer path.
- Document AI only if local-vs-managed benchmark shows meaningful extraction/locator improvement and users explicitly consent to the cross-region processor. Prefer a processor region that meets reviewed data policy.
- Gemini multimodal or speech processing when a specific product need and consent justify the transfer; record exact model ID/endpoint, region, retention and cost. Test South African-language/accent accuracy with synthetic/consented fixtures before claims.
- Cloud SQL only after a migration spike demonstrates a substantial benefit over Firestore for the real schema/history needs and a sustainable monthly total is accepted.
- Agent Search/RAG only after actual corpus-scale retrieval evaluation shows current owner-filtered lexical retrieval misses relevant anchors, with a region and deletion model that fits the product.

### Reject for the current pilot

- Publicly exposing the current SQLite/loopback file server, storing SQLite on Cloud Run filesystem/FUSE, or placing uploaded files into Firestore document bodies.
- Creating Cloud SQL while Firestore is already reported initialized, absent an explicitly approved migration and test plan.
- Defaulting all uploads/audio to Document AI/STT/Gemini; sending private content to a global endpoint as though that meant Johannesburg residency.
- Agent Search configurable pricing or RAG Engine for a one-learner corpus before measurement; arbitrary vendor fallback; unbounded request/minute/page/token use; claims of zero retention or automatic spending cap.
- Any model-generated curriculum, retrieved chunk or job result that can bypass owner/source/revision checks or silently publish as reviewed content.

## Privacy, failure and acceptance gates

Before a small learner pilot, root should demonstrate all of these in its own integration evidence:

1. Two synthetic users: A cannot read/write/delete/export/retrieve B's records when given IDs; UID comes from a cryptographically verified token, never from client fields.
2. Restart/redeploy/reopen: Firestore source revisions, draft version CAS and job state persist; private originals are in GCS. Local `saved` and hosted `saved` copy never contradict service result.
3. Firestore database location and GCS bucket location explicitly confirmed as Johannesburg; every downstream API (Document AI, Gemini/Vertex, STT/TTS) names the actual processor/model/endpoint region and data handling before use.
4. Storage lifecycle text matches seven-day soft delete or a root-verified updated policy; deletion covers Firestore records, GCS live/noncurrent/soft-deleted versions, task payloads, logs, indexes and model retention limits.
5. Queue retries, client duplicate submits, cancellation and stale source revision cannot produce duplicate or obsolete lesson artifacts; private worker rejects anonymous/public calls.
6. Per-user bytes/pages/concurrency/tokens/audio minutes, retry count and max instances cap app-level use; alert plus actual quota reject behavior is exercised. No spend dashboard is described as a hard cap.
7. Secret IAM is exact; no service-account key; logs exclude prompt/text/transcript/token/secret; explicit consent, text alternative and recoverable error state remain available.
8. Benchmarks are synthetic or properly consented; app/source rights, model terms and processor regions are reviewed. Re-run cost worksheet with measured request and storage data after credits assumed zero.

The hosted foundation contract's worker lanes and parent-owned integration/tests are still the implementation authority. This memo supplies a service selection and review checklist; it does not establish a live hosted KAIRO path, data-region compliance, secure two-user isolation, learning outcomes, cost cap or public release.
