# W4 — one account-status request per page

Criterion: Sustainability
Learner need: faster page start (the account status is requested once per document, not once per component)

## Changed files
- studio/src/account/status.ts (new): module-level memo for getAccountStatus(); clears the memo on rejection.
- studio/src/account/AccountBoundary.tsx: boot() reads getAccountStatus(); the status fetch no longer takes the abort signal. Progress fetches are unchanged.
- studio/src/account/AccountPage.tsx: status effect uses getAccountStatus() with an `alive` flag in place of the AbortController.
- studio/src/kairo/AppShell.tsx: SessionBadge reads getAccountStatus() (status fetch only).

## Behaviour changes on error (not preserved exactly)
- AccountBoundary: a non-ok status response previously threw an empty Error and showed the fallback text. It still shows that fallback. A network failure previously showed the raw fetch message; it now shows the fallback text.
- AccountPage: unchanged on the visible text.
- AppShell: previously parsed the body even when the status was not ok (and showed the "Local preview" text). It now rejects a non-ok status and shows "Account connection unavailable".
