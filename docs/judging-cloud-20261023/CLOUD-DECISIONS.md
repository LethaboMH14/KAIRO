# Cloud tools that save useful work

Primary documentation checked 23 October 2026. Service recommendations are proposals, not installed/configured features. No billing/account upgrade, paid call, deployment, SDK installation or private-data upload occurred. Current credit balance, account tier, available regions and remaining quotas were not live-queried.

## Recommended shape: improve the app we have

Keep the existing Vite/React/Three.js application. A mobile-friendly web app/PWA is the lowest-rework starting point; add an installable/native route only for a verified requirement or measured device need. Do not rewrite to Next.js, Flutter or React Native because an AI overview calls them best. Offline behavior and hardware access depend on implementation, permissions and platform; neither native nor web guarantees them. [Google's PWA course](https://web.dev/learn/pwa/welcome) explains progressive enhancement; specific device behaviour still needs testing.

Proposed deployment path: **existing client → Firebase Hosting for static assets → authenticated Cloud Run API → durable canonical store + private Cloud Storage**. Firebase Authentication may supply user identity while the backend still uses PostgreSQL. Auth and database choices are independent. The core blueprint already proposes PostgreSQL; keep that decision visible rather than silently adding Firestore as a second source of truth. Select managed PostgreSQL only after a measured budget/region/backup decision; a synthetic reviewer demo and a private learner pilot have different requirements.

Cloud Run container-local JSON/SQLite is not a durable shared database: its writable filesystem is in memory and disappears when the instance stops. The current loopback preview also lacks production per-user authorization. Merely deploying the container does not solve either. [Cloud Run runtime contract](https://docs.cloud.google.com/run/docs/container-contract#file_system).

## Services to defer unless a specific requirement earns them

No GKE cluster, always-on GPU VM, video-generation pipeline, full agent platform, complex API gateway, separate vector service or BigQuery ML is needed to finish the first source lesson. Paid Cloud Armor/API management may later help edge abuse controls, but cannot replace authorization or secure queries. Do not train a SASL model from unlicensed video. Do not use Remote Config personalization as a learning model: [its own guidance](https://firebase.google.com/docs/remote-config/personalization/use-cases) recommends large activity levels and optimizes Analytics events, not validated educational outcomes.

For long repeated prompts, [Vertex context caching](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/context-cache/context-cache-overview) may reduce repeated input work, but storage/TTL/minimum-input rules and model availability can make it inappropriate for short lessons. First use exact source/revision/prompt/model cache keys and measure misses. Never share private results across learners by text hash alone.

## Free/local alternatives that fit

- Existing local OCR/extractors + reviewed text: no incremental cloud API cost and minimal change. Keep malformed file/time/size limits. Cloud OCR is an optional quality comparison, not mandatory for every passage.
- Browser narration + captions: useful fallback; installed voice/OS can still require network and pronunciation varies. Never label all browser TTS offline.
- Existing SQLite/FTS: continue useful bounded local lookup. PGlite/pgvector probe is an isolated experiment, not a newly installed production model/store. Use lexical search before paying for a vector platform without retrieval-evaluation evidence.
- [Supabase free PostgreSQL](https://supabase.com/pricing): possible development alternative aligned with the proposed PG model, but free DB size is 500 MB and free projects may pause after inactivity. Third-party usage is not Google credit and needs region/auth/backup review. Choose one canonical store, not Firestore + Supabase + Cloud SQL for the same state.
- [OSV-Scanner](https://google.github.io/osv-scanner/usage/) and [Trivy](https://trivy.dev/latest/docs/): local/CI dependency/container/secret evidence. They still need pinned versions, database freshness and finding triage. No scanner was installed or run here.
- [ZAP](https://www.zaproxy.org/): free/open-source dynamic testing candidate for a later explicitly authorized synthetic staging target. Do not scan third-party sites or use browser-driven tools to bypass this session's observation restriction.

## Cost examples: small calculations, not a quote

Use gross post-free-tier cost to show sustainable economics even while credits cover invoices. For a defined synthetic 100-session experiment, assume 3,500 newly synthesized characters per session: 350,000 total. At published marginal rates after allowances, Standard is $1.40, Neural2 $5.60, Chirp 3 HD $10.50 for that text volume. Current listed monthly free limits are 4M/1M/1M respectively, but shared actual remaining quota is unknown. Retries and repeated synthesis add volume; media delivery/storage are separate. [TTS pricing](https://cloud.google.com/text-to-speech/pricing).

Illustrative OCR: 100 lessons × 4 pages = 400 pages. At $1.50/1,000 pages, gross OCR processing is $0.60 before applicable allowances; layout/custom-form models are different SKUs. This is not a total ingest bill or accuracy guarantee. [Document AI pricing](https://cloud.google.com/products/document-ai/pricing).

Assets: 10 MB of optional media downloaded 1,000 times is about 10 GB transferred before cache/compression. Asset delivery can exceed database costs; measure actual bytes and cache policy. Storage pricing explicitly includes operations and network, not just stored GB.

Model cost: `sessions × (input_tokens × input_rate + output_tokens × output_rate + tool/retrieval charges)` with rates normalized to the provider's token unit. Add failed/retried jobs, speech, storage, egress, builds/scans, logs and database runtime. Do not assign a model rate from an old screenshot or invent all-inclusive cost per student.

Proposed experiment envelope only, **not authorization to spend**: target at most $30 gross for a first small controlled staging/pilot experiment, with category estimates and a stop owner agreed before deployment. Keep the existing project alert, per-user/day server quotas, max instances/timeouts, bounded token/audio/page lengths and cache isolation. [Budget alerts are notifications](https://docs.cloud.google.com/run/docs/jobs-cost-optimization), not a cap. That current Cloud Run guide also describes Cloud Run spend caps; confirm availability/scope in this project before relying on one, because downstream services and connectors can still cost money and cap enforcement interrupts service.

Plan for the credit-expiry day: permitted local sample/reading fallback, source/notes export, protected data retention/deletion, no unexpected paid upgrade, and a measured paid operating option only with explicit authorization. A permanent free production service is not promised.
