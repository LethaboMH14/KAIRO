# Independent audit of four AI capability claims

Checked 2026-10-24. Scope: four claims in the attached pasted research text (lines 258–260, 292, 294–299, plus SASL implementation claims at 301–303). This is an evidence review, not implementation or a model trial.

## Verdicts

| Claim | Verdict | Evidence and usable boundary |
|---|---|---|
| XTTS-v2 / MMS provide South African language TTS with commercial coverage | **Unsupported as stated; do not present as ready.** XTTS-v2 card lists 17 languages (English, Spanish, French, German, Italian, Portuguese, Polish, Turkish, Russian, Dutch, Czech, Arabic, Chinese, Japanese, Hungarian, Korean, Hindi). It does not list Afrikaans, isiZulu or isiXhosa. Its card names the Coqui Public Model License; Coqui's model registry marks XTTS-v2 CPML and requires terms acceptance. This is not a general commercial-use clearance. MMS TTS claims 1,107 languages, but that aggregate does not prove the exact target-language checkpoint, quality or permitted commercial use. MMS TTS card says CC-BY-NC-4.0, which is noncommercial. **Candidate:** per-language `facebook/mms-tts` checkpoints only for languages actually present in Meta's official TTS coverage list and only for noncommercial evaluation unless separate permission applies. Language coverage is not quality evidence. |
| Chronos predicts the exact time a learner will master a concept | **False capability claim.** Amazon describes Chronos as a probabilistic time-series forecasting family. It forecasts future values from historical series; it has no inherent construct for mastery, educational validity, or exact event-time estimation. A Chronos forecast could at most be an experimental baseline after defining a repeated numeric target and outcome label. **Candidate:** Chronos-Bolt or a simple statistical baseline on temporally held-out learner data, reporting probabilistic forecast error and calibrated intervals. No current mastery predictor is validated. |
| Embedding cosine similarity yields an exact employability/job-fit percentage | **False interpretation of a similarity score.** The BGE model card describes embeddings for semantic retrieval and explicitly cautions that absolute similarity values do not directly indicate sentence similarity; relative ranking is the useful signal and thresholds must be chosen on task data. Text similarity is not probability of being employable or qualified. **Candidate:** use an embedding model such as BGE only to retrieve/rank relevant job requirements, then show requirement-level evidence and missing information. Any percentage requires a separately defined, outcome-labeled and calibrated assessment and must be named as an estimate with uncertainty. |
| `google/vit-pose-base` + VideoMAE constitutes SASL translation | **Unsupported model identity and category error.** Exact repo ID `google/vit-pose-base` was not verified in official sources; no guessed replacement is assumed. VideoMAE is a general video representation/classification architecture. Hugging Face's task documentation describes video classification as assigning a class to an entire video, and its example checkpoint predicts one of 400 Kinetics action classes. Pose estimation/landmark extraction plus generic video classes do not provide SASL glosses, grammar, facial/nonmanual markers, or translation. **Candidate:** no ready SASL translator established here. A pose/hand/face tracker and VideoMAE can be evaluated only as generic feature extractors, with community-authored SASL data, qualified annotation, language and signer split evaluation, and Deaf-community review. Do not call the current idea SASL translation. |

## Minimal evaluation contract before any learner-facing claim

1. **Define the target and unit.** TTS: exact language, dialect/register, text domain, consented speaker, pronunciation and prosody outcomes. Learning forecast: an operational mastery label, observation window, forecast horizon and intervention context. Job alignment: versioned job requirements, explicit skill evidence, missingness and human-defined fit rubric. SASL: direction (sign-to-text or text-to-sign), language variety, gloss/translation target, conversational context and intended audience.
2. **Use a locked, leakage-resistant holdout.** Split by person/speaker and time where relevant; keep all records from one learner or signer within a partition. Freeze preprocessing and model versions before the final test. Compare against transparent baselines and human/majority baselines. No random clip-level split where adjacent frames or repeated learner attempts can leak.
3. **Report task metrics and calibration.** TTS: intelligibility (language-specific transcription/WER or CER), naturalness ratings and pronunciation error, with native-speaker blinded review. Learning: MAE/median absolute error for time outcomes, event concordance where censoring exists, prediction interval coverage/width and calibration, plus performance by cohort and missingness. Job: requirement-level precision/recall and ranking metrics against blinded expert labels; do not convert raw cosine into a probability. SASL: signer-held-out gloss error (WER) and translation metrics plus Deaf fluent signer ratings of grammaticality, meaning and facial/nonmanual adequacy; machine metrics alone are insufficient. Include uncertainty intervals and subgroup results.
4. **Record missingness, abstention and harm.** State who has no usable history/video, how silence/poor capture/unsupported language is handled, when the system abstains, and whether errors differ by accent, dialect, age, disability, skin tone, signing style or device quality. Do not infer learner traits or career destiny from sparse interaction traces.
5. **Clear data and model rights.** Record exact checkpoint/revision, model and code licenses separately, training/evaluation data provenance and consent, attribution, permitted use, retention/deletion, privacy/region and voice/face biometric treatment. For MMS TTS, verify each ISO code in the official TTS list; the public HF card says CC-BY-NC-4.0. For XTTS-v2, CPML is not assumed commercially cleared. Obtain independent legal review where rights remain ambiguous.
6. **Require real human acceptance.** TTS needs paid/consented speakers and fluent native listeners across target dialects. Learning/job use needs learners and relevant educators/career advisers, with clear non-deterministic framing. SASL requires Deaf SASL signers and community organizations in dataset design, annotation, evaluation and release approval, compensating contributors. A prototype score or model card cannot substitute for this evidence.

## Evidence boundaries

No model was downloaded, run, trained or provisioned. The Hugging Face connector's model search call was unavailable in this session; web search covered official model cards, repositories and primary papers. No language-specific MMS TTS quality, commercial permission, local benchmark, SASL translation performance or learner usefulness was tested. These are research candidates and evaluation requirements, not production recommendations or current product behavior.
