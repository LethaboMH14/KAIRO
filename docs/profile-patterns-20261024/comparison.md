# Evidence profile and opportunity patterns

Official product and standards documentation checked on 2026-10-24. “Take for KAIRO” is a design inference from documented features, not a claim of user validation or outcome improvement.

| Product/pattern | What official documentation says | Evidence, role, opportunity, privacy and time context | Useful pattern for KAIRO | Trade-off / avoid copying as a claim | Small acceptance check |
|---|---|---|---|---|---|
| LinkedIn profile: Featured work and Skills | The Featured area can surface authored posts/articles, external links and media; it can be reordered/removed. One current Help page says Featured is limited to Premium Business, Sales Navigator and Recruiter, while other Help text describes general Featured workflows. Skills can be added to a profile and endorsed by first-degree connections. | Profile sections can associate a skill with experience, education or projects. Visibility follows profile controls; a featured sample is not a verified credential. Availability documentation is inconsistent, so do not assume everyone can use the feature. The profile positions member identity and professional milestones together. | Give the learner a short, curated “show these items” ordering with title, contribution, evidence and date; provide small, concrete skill/role language alongside rather than replacing work samples. | A profile skill or endorsement is a person’s claim/social signal; it does not establish independent assessment. Keep any visibility caveat close to share action, not buried in a settings page. Do not promise discovery or hiring. | In a task, learner can select one project/evidence item, preview its title and claim level, then remove it before sharing; a self-added skill is visibly distinct from a credential. |
| GitHub profile: profile README and pinned repositories | GitHub allows a profile README and pinned repositories/gists; the profile reference says up to six public repos/gists can be pinned and a public repository must be owned or have recent qualifying contribution. Public profile information is visible to all GitHub users. | Pinned projects lead with work artifacts and repository context (including first lines/stars); contribution activity may be displayed, including anonymised private activity if the user opts in. GitHub warns that making a profile private does not hide public-repository activity. | Let a learner curate a handful of artifacts and explain their own contribution, tools, context and limits; offer a plain README-like project summary and stable source link. | Stars, commit counts, repository visibility or activity are not a skill rating. “Private profile” does not erase public work elsewhere. Do not leak raw source records or imply KAIRO's replay data is a GitHub contribution. | Preview shows only selected artifacts and a contribution note; deselecting an item removes it from the generated view and the view contains no unselected repository/run history. |
| Behance portfolio projects | Behance describes a Project as a themed grouping of images, text, video and other media, each with a share URL. Public projects appear on a profile and are public by default. Current project settings also document Everyone, Link Only, Password Protected and Private options; a public profile remains searchable even if some projects are hidden. | A portfolio can make a project narrative and visual output the unit of evidence. Visibility applies per project, and link-only access does not expire according to the Pro guide; a public profile is not wholly private. | Let the learner make a compact story: purpose → own role → artifact → result/evidence → what is not proven. A selected-item view is more useful than exporting the whole private activity timeline. | Public-by-default publishing and non-expiring links are risky defaults for learner material. Do not silently copy source uploads, collaborators’ work or proprietary work into a portfolio. | New evidence begins unshared; learner can inspect audience, exact items, any embedded content and the link lifetime before confirm. Test that removing an item from a share excludes it without deleting the underlying private record. |
| Credly and 1EdTech Open Badges | Credly documents that earners can set badges public/private and share them; issuer-controlled credential contents cannot be edited by the earner. Open Badges 3.0 defines achievement, issuer, learner, evidence, dates, validity and credential status/verification metadata. | A trusted issuer attestation is a different claim type from a learner’s practice log. Badges can have issuer-defined criteria, evidence and expiry/status; a badge can become private or be restricted by its issuer. An externally verified claim depends on issuer identity and credential status, not a KAIRO label. | Reserve “verified credential” wording for an actual credential that a compatible verifier checks against issuer and status. Show issuer, criteria/evidence, issue/expiry/status and verification timestamp. | A badge-looking icon or JSON record alone is not verification. A completion badge for submission may only represent submission; even Handshake documents this distinction for its AI Project Builder badge. KAIRO has no right to issue a school/employer credential by design alone. | A credential cannot render “verified” if signature/issuer/status validation is absent, stale, expired or revoked; absent verification it displays as a link/claim with an explicit unverified label. |
| Handshake profile and job discovery | Handshake documents Community, Employers and Private visibility; students can change their privacy setting. Employers must be approved by the institution and students must opt to share for employer profile access. The platform describes profile-based recommendations, job interests (role/type/location), employer search and employer outreach. | Student profile information includes student-entered and school-synced sections. Employer visibility does not mean all Handshake users or the public; school relationship gates matter. Job interests and advertised opportunities are separate from evidence of capability. Current profile docs say private is a default in some institution-created account circumstances. | Keep opportunity preferences (role, type, location, work setting) in a separate panel from evidence claims. Show source, date checked, stated close date and availability confidence. Add an explicit audience step, default private, with a preview for a named/selected employer. | Handshake is institution-mediated; KAIRO must not borrow its trust signal, employer reach, job feed or outcomes. Recommendations and recruiter outreach are not a guarantee. No FNB partnership, WIL acceptance or automatic application is implied. | With profile private, no employer view is produced. A learner can share one selected item only to the approved test recipient after a clear confirmation; an expired/unverified opportunity is labelled and cannot be presented as currently open. |

## Cross-pattern conclusions

1. **Work before labels:** a project or replayable artifact plus contribution, source/context, date and limits is more inspectable than a bare skill chip. Keep the skill label optional and distinct.
2. **Curation is separate consent:** curate while private; the user should see the exact recipient, selected fields, accessible artifacts and expiry before granting access.
3. **Claims have levels:** self-report, locally replay-consistent practice, learner-reported review, and externally issuer-verified credential should never collapse into one “verified” chip.
4. **Roles are not courses:** role criteria describe an opportunity's requested work; course/module metadata describes learning context. A course title or selected module does not establish an employment skill.
5. **Freshness belongs to dated facts:** show evidence completion/update and verifier check dates; honor issuer expiry/revocation. For vacancies, keep the original posting date, checked date and stated closing date separate; no date should be invented.
6. **Keep opportunity choices actionable:** let a learner save an interest or open the original advert. Avoid match percentages, inferred eligibility, auto-applying, or implying a school/employer has endorsed KAIRO.
