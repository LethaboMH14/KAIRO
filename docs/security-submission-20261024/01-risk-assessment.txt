KAIRO handles private study uploads, extracted text, reviewed source revisions, AI-generated lessons and learner working. Our security priorities are preventing another learner from accessing these records, protecting account sessions, preventing malicious documents or AI output from executing actions, and bounding processing costs. The current pilot uses fictional judge accounts and an IAM-private Google Cloud Run service. Private APIs require Firebase-verified sessions and server-derived owner identity; changing a course code, record ID or client field must not grant access to another account.

We use OWASP API Security Top 10 (2023), ASVS 5.0, OWASP LLM Top 10 (2025) and NIST SSDF as engineering references. We minimise model input, require explicit consent for cloud lesson/help/voice processing, and retain source citations and revision checks. Camera access is optional local hand tracking: no video recording or camera-frame upload is implemented; microphone permission is disabled. Residual risks include document-parser vulnerabilities, misleading model explanations, broad server permissions, account abuse, and incomplete end-to-end deletion/retention workflows. We do not claim POPIA certification, comprehensive OWASP compliance or quantum-safe operation.
