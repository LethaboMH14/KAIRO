We model the boundaries between learner browser, Firebase authentication, Cloud Run API, Firestore/GCS owner records, the import queue/parser and Google model/speech APIs. Main abuse cases are object-ID substitution, forged enrolment/progress, stolen or revoked sessions, cross-origin mutations, malicious uploads, prompt injection, fabricated citations and excessive resource use. MITRE ATT&CK informs account/infrastructure scenarios; MITRE ATLAS informs AI-specific scenarios. These mappings guide investigation rather than prove that an attack occurred.

The application derives ownership from a verified session, not submitted UID fields. Queue jobs require the expected service-account identity. User documents and goals are untrusted data; model output has no connected command/tool execution and is checked against the supplied source citations. We preserve learner work on version conflicts rather than silently overwrite it. Design review identified a login/recovery throttling gap: rotating emails bypassed the original pair-based limit. We reproduced and corrected it with independent account, client and process-wide budgets. Distributed throttling, stronger parser isolation, finer runtime permissions and application-level audit events remain planned hardening.
