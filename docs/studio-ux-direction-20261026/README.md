# KAIRO: clear teaching, contextual studios and one learning journey

26 October 2026. Root codex-full-integration-20261025-f; model/effort not exposed (unknown). Design/research package: no app routes or runtime replaced by this proposal. The user confirms KAIRO visible beside the model with a compact mode. Selected C pathmark, Manrope and Chalk/Moss/Sage/Copper remain authoritative.

## What is wrong now

The source-confirmed issue is information composition: parts list, context metadata, prepared guide, lesson sequence, AI consent/questions and practice all compete in a long view. The motor itself works, but its teaching and navigation are spread out. StudioCompanion defaults avatar=false and passes a portrait; its lazy RainStage is behind Show KAIRO in 3D. RainStage has targets=[]: accurate motor/pump pointing is not connected. No historical reason for that default is assumed. Two separate live WebGL canvases need measured performance before making both continuously render.

## Recommended studio

Keep the model and actual KAIRO visible together. Use three stable task modes: Learn, Explore, Practise. Parts is a searchable list/select, never a radial list of every component. A selected part has a visible name and outline; colour is supplemented by name/shape/state. Open Studio tools to reveal up to five labelled actions: Explain, Look inside, Try, Practise, Source. Selecting one closes the arc and replaces the single contextual card, rather than stacking panels. The arc is a shortcut, with the same labelled actions available in a conventional toolbar/list. It does not replace global navigation.

Explain shows a short source-grounded explanation, an optional prepared diagram/clip, source locator, Play/Pause/Stop and Ask KAIRO. Look inside changes an existing supported model view; disabled controls explain unavailable geometry. Try exposes only the chosen experiment and its assumptions, units, accepted ranges and reset. Practise asks for a prediction/explanation, then separately shows feedback and an explicit save. Source opens the exact reviewed excerpt/revision; returning preserves the part and work. No mastery or employer-validation claim is created by completion.

The card sits in a stable nearby safe area, with a leader to the selected part when visible. Rotation must not cause jitter or chase the model across the screen. If a part moves offscreen, dock the card and keep its label; offer Focus part. Never obscure the part, cover KAIRO, or leave a panel outside the viewport. One click selects; a drag or orbit must not accidentally select or open tools. Escape closes the top transient layer and returns focus. Opening another part cancels pending answers and stops obsolete narration. Closing the card stops its narration; opening a menu need not unexpectedly interrupt the lesson.

On phones, use a compact model/KAIRO stage above a dismissible bottom sheet with labelled actions. No gesture-only long press, mandatory hover, or tiny curved targets. Reading mode keeps all sources and saved practice without WebGL. Large text and translated labels may turn the arc into a list; spatial elegance must not override access.

## Formats: use each for the right task

| Pattern | Good use | Avoid |
|---|---|---|
| Tabs/segmented buttons | A few stable modes: Learn, Explore, Practise | Hiding every feature in one tab bar |
| Searchable select | Parts, modules, role selection with many choices | Replacing narrative teaching with long dropdowns |
| Half-circle action menu | Five frequent actions for a selected model part | Global app navigation or dozens of parts |
| Nonmodal popover/side sheet | Contextual explanation while the model stays usable | Blocking the whole stage for a definition |
| Bottom sheet | Phone controls and explanation | Covering the entire model with no close affordance |
| Disclosure/accordion | Source IDs, assumptions, advanced settings, full requirements | Hiding required warnings, consent or primary actions |
| Hover/focus tooltip | Brief label or unit hint; also appears on keyboard focus | Essential lesson information or touch-only actions |
| Dialog | Consent, destructive changes, protected multi-step decisions | Every card, chart and definition |
| Inline editing | Reviewed text, notes, lesson wording with save status | Silent source mutation or citations changing on edit |
| Timeline/list | Saved work, attempts, opportunities | Implying skill assessment from completion metrics |

## Typography, icons, selected states and motion

Use bundled Manrope, not network fonts. Proposed type scale12/14/16/20/28/36; body16–18 on reading surfaces, line-height1.5–1.65, headings medium/semibold, no all-caps paragraph labels or tiny grey technical prose. Prose around60–70ch. Stage captions are resizable and never baked into an image. Maintain selected C colours; graphite/moss on chalk for small text, sage/copper decorative until actual contrast is checked.

Keep one outline SVG icon family (existing Lucide is a candidate), 20/24px grid, consistent stroke and rounded ends, with persistent action labels. No emoji or changing metaphors for the same action. Filled or bordered selected state plus text/aria-pressed/current, not colour alone. Buttons have hover, focus-visible, disabled reason, pending and success/conflict states. Icon-only close buttons receive explicit names. Touch targets aim44px, verify actual breakpoints. Global navigation remains stable and searchable; the radial menu is local to the studio.

Animate a cause and its effect: selection outline -> focused explanation -> diagram step -> learner prediction. Proposed menu/card transitions around150–220ms; reduced motion uses immediate state changes. Do not stream moving particles, idle teachers and rotating machinery merely as decoration. Keep audio, captions and diagram steps on one shared timeline where really supported; mark authored clips separately from generated answers and simulated physics.

## Scenario acceptance before runtime replacement

1. First-time engineering learner sees own modules, not every course in the product.
2. Guest uses uploaded material without fabricated curriculum or skill history.
3. Native seven-page PDF retains late native text; incomplete scanned pages visibly need review.
4. Selecting a rotor opens only relevant actions; no hover required to discover the tools.
5. Drag-to-orbit does not open a menu or submit an answer.
6. Menu fits all viewport edges, zoom200%, long language labels and keyboard-only use.
7. KAIRO compact mode preserves text, source, captions and shared narration state.
8. Source changes invalidate old teaching answers/work saves rather than quietly reusing them.
9. Provider offline/refused/consent revoked leaves local reading and prepared guidance usable; cancellation ignores late responses.
10. Slow device/WebGL failure switches to labelled illustration and full reading/practice controls; no data loss.
11. A pump assumption or visual arrow is never presented as a measured result.
12. Mobile sheet closes and returns focus; keyboard does not hide typed question/save.
13. Attempts and evidence retain dates/source/assistance; linking to a role does not certify skill.
14. Opportunity expired or source stale cannot be shown as currently open; original source link stays inspectable.
15. Language missing or transcript uncertain stays editable; SASL camera/recognition remains distinct and honestly unavailable unless separately validated.

## Real product references and what transfers

- [Shapr3D adaptive UI](https://support.shapr3d.com/hc/en-us/articles/7873882619548-Adaptive-user-interface): tools change with selection; take contextual relevance, not CAD complexity or unverified speed claims.
- [Onshape context menus](https://cad.onshape.com/help/Content/Home/context_menus.htm): actions tied to entity/context; provide visible touch/keyboard equivalents instead of copying right-click dependence.
- [Blender UI and pie menus](https://developer.blender.org/docs/release_notes/2.80/ui/): radial access for a bounded action set. The official page was search-indexed but direct fetch failed; do not infer new version-specific behavior.
- [Notebook/Gemini mind maps](https://support.google.com/gemininotebook/answer/16212283?hl=en): source-derived overview, collapsible detail and selected-node questions; KAIRO adds the grounded studio teaching journey.
- [Linear peek](https://linear.app/changelog/2019-09-23-improved-peek): inspect detail without losing the current list; use explicit click/touch access as well as hover.
- [Material bottom sheets](https://m3.material.io/components/bottom-sheets/overview): phone-sized contextual work area; app implementation must still be tested for focus, keyboard and overlap.
- [WAI modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): focus moves into a genuine modal, Escape closes it, focus returns; ordinary teaching popovers should stay nonmodal.
- [Radix Popover](https://www.radix-ui.com/primitives/docs/components/popover): feasible accessible UI primitive for a button-triggered rich panel, not a complete radial/3D solution.
- [Floating UI autoUpdate](https://floating-ui.com/docs/autoupdate): anchor placement updates while open and cleans up listeners when closed; add flip/shift/offscreen fallback deliberately.
- [React Three Fiber performance](https://r3f.docs.pmnd.rs/advanced/scaling-performance): on-demand rendering and reuse; a single shared Canvas/viewport is a candidate to measure, not an automatic rewrite or proven faster result.

## Implementation sequence and judging proof

First ship shared studio action/card state in isolation, keyboard/mobile alternatives and unchanged citation/narrator contracts. Then motor host, pump host and scene target adapters. Measure frame time, startup, download and low-device fallbacks before making 3D KAIRO default everywhere. Then material-review/lesson hierarchy, followed by role/evidence/opportunity consistency and settings. Keep real private source revisions and capability labels intact.

Product: task completes and work resumes; Usability: first action/discovery/keyboard/mobile checks; Creativity: contextual KAIRO teaching and purposeful spatial tools; Intelligence: cited, context-sensitive response rather than ornamental menus; Sustainability: bounded rendering/model usage; Impact: reading, language and low-data alternatives with human validation still open; Presentation: actual prototype and labelled concept boards. None of these are official judging scores or measured learning gains.
