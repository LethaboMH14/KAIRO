# Learner-language audit

Source-only review of current learner-facing wording in the computer-science home, teacher settings/reader/provider, source workspace, lesson workspace, progress page, and pathways page. Findings below are limited to labels or states that can mislead, hide a recovery step, or make an otherwise useful action harder to understand. They are not claims about rendered behavior: no browser, screenshot, or assistive-technology run was performed.

## Findings

1. **Prototype language in the teacher introduction** — [TeacherSettings.tsx:13](../../studio/src/teacher/TeacherSettings.tsx#L13) says “Direct the first working teacher rig.” “Rig” and “working” describe implementation maturity, not what a learner can do, and can make a rehearsal appear production-ready. Suggested wording: “Choose a voice and look for your guide, then try the current preview.” Keep the same-character/rehearsal note at line 18, so a future look choice is not mistaken for an already-switched model.

2. **“Natural voice” blurs the kind of speech** — [TeacherSettings.tsx:15](../../studio/src/teacher/TeacherSettings.tsx#L15) labels the section “Natural voice,” while line 16 clarifies Google HD is synthetic speech and browser voices are installed services. Suggested heading: “Read-aloud voice.” Keep the explicit synthetic-speech, consent, processing, language availability, and pricing disclosures; this is a heading change, not a reason to shorten those limits.

3. **Cloud generation has no recovery wording beside its disabled state** — [SourceWorkspace.tsx:37](../../studio/src/workspace/SourceWorkspace.tsx#L37) shows “Cloud generation is off in this session” while the cloud button is disabled; a local-reading action follows. A learner may stop without noticing that the no-cloud option still works. Suggested text: “Cloud lesson generation is unavailable now. You can still create a local reading lesson below.” Keep the reviewed-text consent and the no-cloud distinction.

4. **The lesson mode can sound like a quality guarantee** — [LessonWorkspace.tsx:38](../../studio/src/workspace/LessonWorkspace.tsx#L38) displays “AI generated · source cited.” A citation shows where to check a passage; it does not by itself verify every generated explanation. Suggested label: “AI draft · review the cited passages.” Keep the existing coverage and review warnings at line 43 and the original-source links.

5. **The lesson export click has no visible result state** — [LessonWorkspace.tsx:33,37](../../studio/src/workspace/LessonWorkspace.tsx#L33) creates a Blob and clicks an anchor, but exposes no status after “Export notes.” Anchor activation does not establish that a browser saved the file. Suggested post-click status: “Download requested. Check your browser downloads.” Use the same wording for **“Export marks”** in [SourceReader.tsx:15,28](../../studio/src/teacher/SourceReader.tsx#L28), which also has no result message; consider renaming that action “Export highlights and saved annotations.” Do not say the file was downloaded unless the browser confirms it.

6. **Progress can show a save receipt after a read failure** — [ProgressPage.tsx:8,13](../../studio/src/profile/ProgressPage.tsx#L13) sets an error if saved progress cannot be read, but always renders “Saved on this device.” That conflicts with the visible alert and may make an empty fallback look like recovered history. Suggested state-aware label: “Saved in this browser” only after a successful read/write; when reading fails, replace it with “Saved progress could not be read.” This requires state handling, not just copy.

7. **“Supported” is ambiguous in progress totals** — [ProgressPage.tsx:14–15](../../studio/src/profile/ProgressPage.tsx#L15) uses “questions supported on first try” and “Latest supported.” The model counts whether the first and last recorded answer were correct; “supported” can sound like help was provided. Suggested labels: “Correct on first try” and “Correct on last try,” with the existing retry count retained. Keep the explanation that first attempts and retries are recorded separately.

8. **A parse failure is described as storage being unavailable** — [LessonWorkspace.tsx:25](../../studio/src/workspace/LessonWorkspace.tsx#L25) catches both JSON parsing and storage access errors, then says “Browser storage is unavailable; export your notes before leaving.” The cause may instead be unreadable saved data; the current catch also proceeds to mark loading complete, after which the save effect at line 29 may write the fallback state. Fix the recovery flow before polishing this message: preserve unreadable saved data and do not overwrite it automatically. Then use cause-accurate wording such as “Saved lesson data could not be read. It has been left unchanged; export any notes you can still open.” This needs behavior ownership, not a copy-only patch.

9. **“Build the proof” suggests stronger evidence than the page creates** — [RolePathways.tsx:18,24](../../studio/src/pathways/RolePathways.tsx#L18) pairs “Build the proof” with a percentage called “Your evidence coverage.” The page later correctly says levels and notes are self-reported and the score is not independent skill verification. Suggested heading: “Build a record you can explain” and score label: “Coverage in your KAIRO practice rubric.” Keep the nearby rubric formula, unknown-evidence explanation, and employer/ATS/verification caveats.

10. **The link button does not name the action's limited effect** — [RolePathways.tsx:23](../../studio/src/pathways/RolePathways.tsx#L23) says “Confirm practice link”; the surrounding copy explains that a link is for reference and does not alter evidence level or coverage. Suggested button: “Link this practice run for reference.” Keep the adjacent no-coverage-change explanation and retain the run/scenario/source details.

## Suggested follow-up scopes

- A copy-only follow-up can change teacher labels/introduction, cloud-unavailable recovery copy, lesson provenance wording, export labels/status text, progress metric labels, and pathways wording. Proposed isolated paths: `studio/src/teacher/TeacherSettings.tsx`, `studio/src/teacher/SourceReader.tsx`, `studio/src/workspace/SourceWorkspace.tsx`, `studio/src/workspace/LessonWorkspace.tsx`, `studio/src/profile/ProgressPage.tsx`, `studio/src/pathways/RolePathways.tsx`. Obtain a fresh bus claim before touching these shared UI files.
- The two progress/read-error findings need state/recovery changes, not copy-only edits. Review save timing and unreadable-record preservation separately before assigning language changes.

No consent, accessibility, provenance, independent-review, or credential-limit warning is proposed for removal. This audit makes no claim that copy was tested with learners or validated in a browser.
